# Модуль «План/Факт СМР» (RBI Platform)

Модуль планирования и факта строительно-монтажных работ внутри каркаса **RBI Platform**:
загрузка ВОР из форм заказчика, контуры объёмов, согласование ПТО → РП с неизменяемым baseline,
нормы и график, факт прораба, сверка контуров и дашборд руководителя.

## Как запустить локально

Облако не обязательно: приложение работает в локальном режиме, данные лежат в IndexedDB браузера.

```bash
# из корня репозитория: любой статический сервер
python3 -m http.server 8765
# открыть http://127.0.0.1:8765/index.html и выбрать «Работать локально»
```

Облачная синхронизация включается входом в облако RBI (Supabase) и требует применённых миграций
из `sql/`.

## Где что лежит

| Путь | Что это |
|---|---|
| `src/modules/plan-fact/**` | Исходники модуля на TypeScript: домен (чистые функции) и панели разделов |
| `js/modules/plan-fact/index.js` | Тонкая обёртка, через которую ядро подключает собранный бандл |
| `js/dist/plan-fact.js` | Сборка модуля (Vite), её и грузит платформа |
| `sql/015`, `sql/017`, `sql/018`, `sql/019` | Миграции модуля: синхронизация, контуры и утверждение, hardening, справочник работ |
| `construction-platform/ВОР_*.csv`, `формулы.xlsx`, `бомба.xlsx`, `макросы.xlsm` | Синтетические файлы для проверок импорта (данные выдуманы) |

## Разделы модуля

**Сводка** — дашборд руководителя: выполнение по проекту, сверка контуров, объёмы по единицам
измерения, работы, карточки объектов. **ВОР** — разбор формы заказчика (XLSX/CSV), колонки и шаблоны,
ручное сопоставление работ. **Контуры** — пять контуров объёмов, ввод прямо в таблице, сверка с порогами,
утверждение РП. **Справочник** — виды работ как данные и связки названий. **График** — ГПР по этажам
и нормы. **Прораб** — факт со сторно. **План/факт** — свод план-факта.

## Проверки

```bash
npm run check:ts          # типы
npm run test:unit         # 200 тестов домена модуля
npm run build:plan-fact   # сборка js/dist/plan-fact.js
```

Смоуки (`npm run smoke:plan-fact`, `npm run smoke:plan-fact-cloud`) требуют dev-runtime и **реальных
форм заказчика**: они в репозиторий не входят (см. ниже) и лежат локально.

## Чего в репозитории нет и почему

- **Реальные формы заказчиков и ТЗ** — клиентские данные, не публикуются; синтетические фикстуры для
  проверок импорта оставлены.
- **`_ai/`** — рабочие материалы процесса (планы, отчёты, спеки, журнал) — ведутся локально.
- **`node_modules`**, кэши и логи.

## Рамка решений

Модуль реализуется **внутри ядра RBI**, а не отдельным приложением (ADR-015), отклонения от полного ТЗ
зафиксированы в ADR-016: нет отдельного деплоя, расчёт на клиенте, серверная защита — RLS по проекту
и признаку подтверждения, тонкие права остаются клиентскими.
